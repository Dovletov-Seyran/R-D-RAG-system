# Способ проверки

## Первая контрольная точка

1. `python3 scripts/check_docs.py` — обязательные файлы и локальные ссылки документации.
2. `node --check frontend/script.js` — синтаксис JavaScript.
3. Открыть прототип по README и пройти сценарии S01, S02, S05, S07, S08, S09 из [scenarios.md](../product/scenarios.md).
4. Проверить ширину ноутбука и около 390 px.
5. Показать настоящую историю коммитов и Pull Request в GitHub.

Фактические результаты — [docs/verification.md](../../docs/verification.md).

## Проверки следующих этапов

| Компонент | Что проверяем |
| --- | --- |
| Индексатор | Номера страниц сохраняются; фрагменты не пустые; `chunk_id` стабилен при повторном запуске |
| Токенизатор | Лемматизация, сохранение «ЛР3» и номеров ГОСТ, одинаковая обработка запроса и корпуса |
| Поиск | Детерминированный результат; пустой индекс и запрос без совпадений обрабатываются |
| API | Коды 200/400/503, формат `text`/`sources`/`finish_reason` |
| Frontend | Ответ и источники отображаются, ошибка сервера не ломает чат |
| Интеграция | Реальный вопрос проходит через BM25 и LLM и возвращает правильный источник |

Unit-тесты Python запускаются через `pytest` без GPU; LLM подменяется заглушкой.

## Benchmark

### Точка 2

Объём по требованиям курса: 30 документов `D01…D30`, 10 обычных вопросов (у каждого не меньше 3 релевантных документов и эталонный ответ) и 5 вопросов-ловушек без ответа в корпусе. Метрики: Recall@5 и MRR@5 по 10 обычным вопросам, Accuracy ответов по 10 обычным, Correct Rejection Rate по 5 ловушкам. Benchmark запускается в рантайме — из консоли `python -m benchmark.run` и из интерфейса через `POST /api/benchmark/run`. Подробности и формат — [ТЗ точки 2](../../docs/checkpoint-2.md).

### Точка 3

Набор вопросов студентов с эталонными ответами, размеченный командой вручную по реальному корпусу. План — около 60 вопросов: 40 для настройки (dev) и 20 контрольных (holdout), включая 10 вопросов без ответа в корпусе. Формат — [benchmark/README.md](../../benchmark/README.md).

### Метрики поиска

- **Recall@5** — доля вопросов, у которых нужный фрагмент есть среди первых пяти.
- **MRR@5** — среднее значение 1/позиция первого нужного фрагмента (0, если его нет в top-5).
- **Точность отказа** — доля вопросов без ответа, на которые система верно ответила `no_context`.

### Метрики ответа

Оцениваются вручную двумя участниками по шкале 0/1/2: правильность, опора на источник, полнота. Дополнительно — доля ответов с верным источником.

### Эксперименты

| Эксперимент | Что сравниваем |
| --- | --- |
| E1 | BM25 на исходных словах и на леммах |
| E2 | Размер фрагмента: 500 / 1000 / 1500 символов |
| E3 | Добавление заголовков в текст фрагмента |
| E4 | Разные LLM при одинаковом поиске |
| E5 (опционально) | BM25 против векторного и гибридного поиска |

Предварительная цель: Recall@5 ≥ 0.8 на holdout и точность отказа ≥ 0.8. Это план, а не достигнутые результаты.

Отчёт хранит commit, версию корпуса, модель, параметры, результаты по каждому вопросу и время ответа. Holdout не используется для подбора параметров.
