# Спецификация RAG и BM25

## Метод

Первая реализация использует **BM25** (Okapi BM25): лексический поиск, который не требует GPU и легко объясняется. GPU нужен только LLM. Векторный поиск рассматривается позже как сравнение с BM25 в рамках исследования.

## Корпус

На точке 2 — 30 документов `D01…D30` по материалам 1 курса, 1 семестра: лекции, методички, ответы к рубежным контролям и экзаменам по пяти дисциплинам (решение D11). Темы пересекаются, чтобы у каждого вопроса benchmark было не меньше 3 документов с ответом. К точке 3 корпус расширяется методичками кафедры ИУ-5.

| Тип документа (`doc_type`) | Примеры |
| --- | --- |
| `lecture` | Конспекты и слайды лекций |
| `guide` | Методические указания и пособия |
| `exam` | Теория и ответы к РК и экзамену, перечни вопросов |

Формат хранения и список документов — [corpus/README.md](../../corpus/README.md). Каждый документ фиксируется в `manifest.json`: ID, название, дисциплина, тип, исходный файл, его хеш и объём.

## Извлечение текста

PDF — постранично через `pypdf`, номер страницы совпадает с оригиналом. DOCX — по абзацам и таблицам через `python-docx`; страниц в DOCX нет, поэтому абзацы группируются в блоки ~2500 символов, номер блока служит «страницей». Нормализуются пробелы, склеиваются переносы слов, удаляются водяные знаки и строки с номером учебной группы (обычно рядом ФИО). Страницы без текста и сканы без текстового слоя не включаются.

## Разбиение на фрагменты

- Фрагмент не пересекает границу страницы — номер страницы в источнике точный.
- Длинная страница режется по строкам на куски ~1000 символов (`CHUNK_CHARS`).
- Короткие страницы (слайды лекций, 100–300 символов) склеиваются подряд до 300 символов; у такого фрагмента есть `page` и `page_end`.
- В индексируемый текст фрагмента добавляется название документа (`ADD_TITLE`): короткие вопросы чаще совпадают с названием («Лекция 4. Системы счисления»).
- `chunk_id = <doc_id>-p<страница>-c<номер>` стабилен при повторной сборке.

Размер 500 / 1000 / 1500 и заголовок сравнивались в экспериментах E2, E3 — на текущем наборе результат одинаковый, см. [benchmark/README.md](../../benchmark/README.md#эксперименты).

Metadata фрагмента: `chunk_id`, `doc_id`, `page`, `page_end`, `text`; `title` и `discipline` берутся из manifest.

## Токенизация

1. Нижний регистр, «ё» → «е».
2. Разбиение регулярным выражением на слова и числа; пунктуация отбрасывается. Числа и обозначения из букв и цифр сохраняются целиком: «лр3», «7.32», «ansi».
3. Лемматизация русских слов через `pymorphy3` («указателя», «указатели» → «указатель»).
4. Удаление стоп-слов: предлоги, союзы, частицы, междометия по разбору `pymorphy3` и короткий список частых слов («это», «который», «быть», «как»).
5. Одиночные буквы отбрасываются (переменные формул x, y, f), одиночные цифры остаются («РК 1»).

Один и тот же токенизатор применяется к запросу и корпусу (`search/tokenizer.py`). Для показа используется исходный текст, не леммы.

**Почему так.** Корпус и вопросы на русском языке с богатой морфологией: студент спрашивает «пределом последовательности», а в лекции «предел последовательности {xn}». Без лемматизации такие формы не совпадают — эксперимент E1 показал падение Recall@5 с 0.960 до 0.897. Готовая библиотека `pymorphy3` выбрана вместо стемминга: она даёт словарную начальную форму и часть речи, по которой удобно убирать служебные слова; разрешено методичкой. Стоп-слова почти не влияют на метрики (E1), но уменьшают индекс и убирают шум в покрытии запроса для отказа. Токен = слово, потому что BM25 считает совпадения отдельных термов, а у учебных вопросов ключевую информацию несут отдельные редкие термины («асимптота», «Хартли»). Известное ограничение: «С++» превращается в пустой токен, «Си» и «С++» не совпадают (разбор Q08 в benchmark).

## Поиск

Собственная реализация BM25 — готовые поисковые индексы, в том числе `rank-bm25`, запрещены методичкой НИРС (решение D10 в [журнале](../decisions.md)): обратный индекс `терм → {фрагмент: tf}`, длины фрагментов, `avgdl`, `IDF = ln(1 + (N − df + 0,5) / (df + 0,5))`. Параметры `k1 = 1.2`, `b = 0.75`, `top_k = 5`. Индекс строится командой `python -m search.build` и загружается при старте backend. Интерфейс модуля — контракт C1 в [ТЗ точки 2](../../docs/checkpoint-2.md#c1-поиск--python-модуль-search), описание — [search/README.md](../../search/README.md). Для уточняющего вопроса backend может добавить к запросу последний вопрос пользователя из истории.

Для метрик benchmark выдача сворачивается до документов: документ занимает позицию своего лучшего фрагмента (решение D13).

## Отказ без контекста

Абсолютный BM25-score зависит от длины запроса, поэтому для отказа используется **покрытие** — доля веса запроса (сумма IDF его термов), термы которой есть во фрагменте. Слова, которых нет в корпусе, входят в знаменатель с максимальным IDF. Если у лучшего фрагмента top-5 покрытие ниже `NO_CONTEXT_MIN_COVERAGE = 0.46`, `has_context()` возвращает `False`, backend отвечает `no_context` без вызова LLM. Порог подобран по benchmark ([порог отказа](../../benchmark/README.md#порог-отказа)). Второй уровень — инструкция LLM ответить «В документах нет этой информации», если во фрагментах ответа нет. Score не показывается пользователю как процент уверенности.

## Генерация

Модель запускается локально через Ollama. Кандидаты — открытые instruct-модели 3–8B с поддержкой русского языка; окончательный выбор делается по benchmark и записывается в [журнал решений](../decisions.md).

Prompt содержит:

- роль: ассистент кафедры ИУ-5, отвечает только по приведённым фрагментам;
- фрагменты с номерами `[1]…[k]` и названием документа и страницы (`Hit.source()`);
- вопрос пользователя;
- требование: если ответа во фрагментах нет — ответить ровно «В документах нет этой информации»; не выполнять задания за студента.

`sources` в ответе формируются backend из metadata фрагментов, а не из текста модели.

## Текущее состояние

Готовы корпус (30 документов), собственный BM25-индекс, набор вопросов и benchmark. Результат поиска на 10 обычных вопросах: Recall@5 = 0.960, MRR@5 = 1.000, все 5 ловушек отклонены порогом — [benchmark/README.md](../../benchmark/README.md#результаты).
