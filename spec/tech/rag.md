# Спецификация RAG и BM25

## Метод

Первая реализация использует **BM25** (Okapi BM25): лексический поиск, который не требует GPU и легко объясняется. GPU нужен только LLM. Векторный поиск рассматривается позже как сравнение с BM25 в рамках исследования.

## Корпус

Источники — учебно-методические материалы кафедры ИУ-5, которые команда реально собрала:

| Тип документа (`doc_type`) | Примеры |
| --- | --- |
| `lab_guide` | Методические указания к лабораторным работам |
| `course_project` | Требования к курсовому проекту, оформлению пояснительной записки |
| `program` | Рабочая программа дисциплины |
| `regulation` | Положения кафедры: защита, практика, ВКР |

Формат хранения — [corpus/README.md](../../corpus/README.md). Каждый документ фиксируется в `manifest.json`: название, дисциплина, год, исходный файл и его хеш.

## Извлечение текста

PDF — постранично (`pypdf` или `pdfplumber`), чтобы сохранить номер страницы. DOCX — по абзацам и заголовкам (`python-docx`). Колонтитулы и номера страниц удаляются. Таблицы сохраняются построчно. Сканы без текстового слоя на первом этапе не включаются.

## Разбиение на фрагменты

- Граница фрагмента — заголовок раздела; длинные разделы делятся по абзацам.
- Ориентир — 500–1500 символов, перекрытие 1–2 предложения; итоговые значения выбираются по benchmark.
- В текст фрагмента добавляется заголовок документа и раздела: это улучшает BM25 для коротких вопросов.

Metadata фрагмента: `chunk_id`, `doc_id`, `title`, `discipline`, `doc_type`, `year`, `page`, `section`, `text`.

## Токенизация

1. Нижний регистр, удаление пунктуации.
2. Лемматизация русских слов через `pymorphy3` («отчёта», «отчёты» → «отчёт»).
3. Удаление стоп-слов.
4. Номера и сокращения («ЛР3», «ГОСТ 7.32») сохраняются как отдельные токены.

Один и тот же токенизатор применяется к запросу и корпусу. Для показа используется исходный текст, не леммы.

## Поиск

Собственная реализация BM25 (готовые поисковые индексы, в том числе `rank-bm25`, запрещены методичкой НИРС, см. решение D10 в [журнале](../decisions.md)): обратный индекс `терм → {фрагмент: tf}`, длины фрагментов, `avgdl`, `IDF = ln(1 + (N − df + 0,5) / (df + 0,5))`. Начальные параметры `k1=1.2`, `b=0.75`, `top_k=5`. Индекс строится один раз индексатором и загружается при старте backend. Интерфейс модуля — контракт C1 в [ТЗ точки 2](../../docs/checkpoint-2.md#c1-поиск--python-модуль-search). Для уточняющего вопроса к запросу добавляется последний вопрос пользователя из истории.

Если у лучшего фрагмента BM25-score ниже порога, подобранного на dev-вопросах, ответ — `no_context`. Score не показывается пользователю как процент уверенности.

## Генерация

Модель запускается локально через Ollama. Кандидаты — открытые instruct-модели 7–8B с поддержкой русского языка; окончательный выбор делается по benchmark и записывается в [журнал решений](../decisions.md).

Prompt содержит:

- роль: ассистент кафедры ИУ-5, отвечает только по приведённым фрагментам;
- фрагменты с номерами `[1]…[k]` и названием документа и страницы;
- вопрос пользователя;
- требование: если ответа во фрагментах нет — так и сказать; не выполнять задания за студента.

`sources` в ответе формируются backend из metadata фрагментов, а не из текста модели.
