## Общая ответственность

Каждый участник понимает путь вопроса от интерфейса до источника и ответа, умеет запустить прототип и объяснить свой компонент. Контракт API согласуется до независимой разработки. Вопросы для benchmark предлагают все участники. Pull Request проверяет не автор.

## Рабочие границы

Каталоги и ведущие участники — в [CONTRIBUTING.md](../CONTRIBUTING.md#зоны-ответственности).

## Порядок совместной работы

1. Вместе принять продукт, сценарии, API и архитектуру.
2. Разбить работу на задачи из [плана](plan.md), завести GitHub Issues.
3. Работать параллельно: frontend — на демо-ответе, backend — на заглушке поиска, RAG — без LLM.
4. Связать компоненты на одном вопросе, затем расширять корпус и запускать benchmark.
