# Спецификация продукта

## Проблема

Учебно-методические материалы кафедры ИУ-5 разбросаны по разным файлам и сайтам: методички к лабораторным работам, требования к курсовым проектам, рабочие программы дисциплин, положения о защите. Это в основном PDF и DOCX. Студенту трудно быстро найти конкретное требование («какой шрифт в отчёте», «что спрашивают на защите ЛР2»). Обычный чат-бот без опоры на документы может уверенно выдумать требование, которого нет в методичке.

## Цель

Дать студенту короткий ответ на русском языке по реальным материалам кафедры и показать, на какой документ и страницу опирается ответ. Если в материалах нет ответа, ассистент говорит об этом прямо.

## Пользователь и польза

| Пользователь | Задача | Польза |
| --- | --- | --- |
| Студент кафедры ИУ-5 | Найти требование, разобрать тему, подготовиться к защите | Ответ за секунды и ссылка на методичку для проверки |
| Преподаватель | Проверить, что ассистент отвечает по материалам | Видны источники каждого ответа |

## Исследовательская часть

Тема НИРС — исследование **эффективности** RAG-системы. Поэтому кроме самого ассистента команда измеряет:

- качество поиска BM25 по методичкам (Recall@5, MRR@5);
- влияние способа нарезки документов (размер фрагмента, учёт заголовков);
- влияние русской морфологии (лемматизация против исходных слов);
- качество итоговых ответов LLM и корректность отказов.

Методика — [spec/tech/testing.md](../tech/testing.md).

## Область MVP

- Вход в систему (на точке 1 — демо-учётная запись).
- Чат: вопрос на русском, ответ на русском, список источников (документ, страница).
- История диалогов с возможностью создать, открыть и удалить диалог.
- Поиск BM25 по подготовленному корпусу методичек кафедры.
- Генерация ответа локальной LLM только по найденным фрагментам.
- Явный отказ, если подходящего контекста нет.
- Корпус: сначала 3–5 документов для интеграции, затем 15–30 документов по нескольким дисциплинам.

## За пределами MVP

Выполнение заданий за студента, загрузка студентом собственных файлов, поиск по интернету, интеграция с электронным журналом, полноценные аккаунты через единый вход МГТУ, обучение собственной модели. Векторный и гибридный поиск могут исследоваться как сравнение с BM25 после получения базовых результатов.

## Критерии продукта

1. Студент проходит основной сценарий без знания архитектуры.
2. У каждого ответа по материалам есть хотя бы один источник с названием документа и страницей.
3. При отсутствии информации нет уверенного выдуманного ответа.
4. Ошибка сервера не ломает интерфейс: можно отправить следующий вопрос.
5. Интерфейс работает на ноутбуке и на телефоне, доступен с клавиатуры.

На точке 1 показывается только интерфейсный сценарий с демо-ответом.
