## Сообщения

- Сообщение студента — справа, подпись «ВЫ».
- Ответ ассистента — слева, подпись «АССИСТЕНТ ИУ-5», под ответом строка «Источник: …».
- Во время ожидания показывается индикатор из трёх точек.
- Текст выводится через `textContent`, поэтому HTML из ответа модели не исполняется.

## Состояния

Пустая история, новый диалог, ожидание ответа, ответ с источниками, ошибка сервера, ошибка входа. Enter отправляет, Shift+Enter переносит строку, пустое сообщение не отправляется.

## Визуальный стиль

Тёмная тема, акцентный цвет `#4bc9e8`, шрифт Inter. Цвета заданы CSS-переменными в `:root` файла `frontend/styles.css`.

## Подключение backend

Единственная точка подключения — функция `askAssistant(question, chat)` в `frontend/script.js`. Она отправляет POST /api/chat на API_URL (по умолчанию http://localhost:8000), передавая вопрос и до 6 предыдущих сообщений без повторения текущего вопроса. Контракт будущего запроса — [spec/tech/api.md](../tech/api.md).

## Дальнейшие улучшения

- Markdown в ответах (списки, код) через безопасный рендер.
- Кликабельные источники с показом найденного фрагмента.

## Контрольная точка 2

Отказ `no_context` выделяется подписью «Нет информации в материалах». Ошибки сервера показаны отдельно и не входят в историю запросов API. Во время запроса повторная отправка заблокирована; переключение диалогов не переносит ответ в другой чат. Максимум — 2000 символов.

Экран Benchmark: режим retrieval/full, положительное целое k (по умолчанию 5), запуск через API, опрос каждые 1,5 секунды, прогресс, четыре метрики и таблица вопросов. null отображается как «Не рассчитано», совпавшие документы выделены. Пример из frontend/mock/benchmark-result.json открывается отдельной кнопкой с явной пометкой «ДЕМО» и никогда не подменяет ошибку API. Проверка: ответ, отказ, ошибки 400/503/500, 409 при занятом benchmark, running/done/error, мобильная ширина 390 px.
