# План и контрольные точки

Точные даты контрольных точек сообщает преподаватель; здесь зафиксированы задачи и их статус.

| Задача | Ведущий | Результат | Проверка | Статус |
| --- | --- | --- | --- | --- |
| CP1-01. Тема, пользователь, сценарии | Frontend | `spec/product/` | Review командой | Готово |
| CP1-02. Архитектура и API | Backend | `spec/tech/architecture.md`, `api.md` | Review потребителями | Готово |
| CP1-03. RAG-спецификация и методика benchmark | RAG | `spec/tech/rag.md`, `testing.md` | Review командой | Готово |
| CP1-04. Прототип интерфейса | Frontend | `frontend/` | Показ в браузере | Готово |
| CP1-05. Оформление репозитория | Backend + все | README, docs, CI, шаблон PR | `check_docs.py`, GitHub | Готово |
| CP1-06. Защита точки 1 | Все | [Сценарий показа](../docs/demo-script.md) | Каждый объясняет свою часть | К защите |
| CP2-01. Сбор корпуса: 3–5 документов | RAG | `corpus/`, manifest | Проверка извлечения страниц | Следующий этап |
| CP2-02. Индексатор и BM25 | RAG | `search/` | Unit-тесты, первые dev-вопросы | Следующий этап |
| CP2-03. Backend `POST /api/chat` | Backend | `backend/` | Тесты API с заглушкой LLM | Следующий этап |
| CP2-04. Подключение frontend к API | Frontend | `askAssistant()` | Сценарии S01, S03, S06 | После CP2-03 |
| CP2-05. LLM и полный RAG | Backend + RAG | Ответ с источником | Ручная проверка на dev | После CP2-02, CP2-03 |
| CP3-01. Расширение корпуса до 15–30 документов | RAG | `corpus/` | manifest, проверка извлечения | Финальный этап |
| CP3-02. Benchmark и эксперименты E1–E4 | RAG + все | Отчёт с метриками | holdout | Финальный этап |
| CP3-03. Итоговые документы и выступление | Все | README, отчёт, демонстрация | Код и документы совпадают | Финальный этап |

Frontend не ждёт модель: работает на демо-ответе. Backend сначала отдаёт ответ с заглушкой поиска. RAG проверяет поиск без LLM. Интеграция начинается с одного вопроса.
