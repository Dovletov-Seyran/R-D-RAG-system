# Benchmark

Проверка RAG-системы на фиксированном наборе вопросов. Запускается **в рантайме** — из консоли или через API backend (требование точки 2, решение D12).

| Файл | Назначение |
| --- | --- |
| `questions.jsonl` | 10 обычных вопросов `Q01…Q10` и 5 ловушек `T01…T05` |
| `run.py` | Прогон и 4 метрики: `python -m benchmark.run` |
| `experiments.py` | Сравнение настроек поиска: `python -m benchmark.experiments` |
| `results/` | Сохранённые прогоны: `<дата>_<режим>.json` и `.md` |
| `questions.example.jsonl` | Пример формата с точки 1, в метриках не участвует |

## Запуск

```bash
python -m benchmark.run                                       # только поиск: секунды, без LLM
python -m benchmark.run --mode full --api http://localhost:8000   # с ответами LLM через backend
```

| Режим | Что делает | Метрики |
| --- | --- | --- |
| `retrieval` | Только BM25-поиск | Recall@5, MRR@5; CRR — по порогу отказа поиска |
| `full` | Поиск + ответ LLM (`POST /api/chat` или `backend.app.rag.answer`) | Все 4: Recall@5, MRR@5, Accuracy, CRR по ответам системы |

Параметры: `--k` (по умолчанию 5), `--model` (подпись модели в отчёте), `--no-save`. Из кода — `run_benchmark(k, mode, answer_fn, on_progress)`, формат результата — контракт C3 в [ТЗ точки 2](../docs/checkpoint-2.md#c3-запуск-benchmark-из-кода).

## Формат вопроса

| Поле | Описание |
| --- | --- |
| `id` | `Q01…` — обычный, `T01…` — ловушка |
| `type` | `normal` или `trap` |
| `discipline` | Дисциплина вопроса |
| `query` | Вопрос своими словами, как спросил бы студент (не копия фрагмента) |
| `relevant_doc_ids` | Документы с ответом, не меньше 3 у обычного вопроса; пусто у ловушки |
| `reference_answer` | Эталонный ответ, проверенный по документам |
| `key_facts` | Ключевые факты для автопроверки ответа; варианты через `|` |

Релевантность размечена вручную: для каждого документа из `relevant_doc_ids` найден фрагмент с ответом (определение, формулировка теоремы, алгоритм). Ловушки похожи на вопросы студента, но ответа в корпусе нет: консультация, двойной интеграл (2 семестр), numpy, нормативы физкультуры, TCP.

## Метрики

| Метрика | Вопросы | Расчёт |
| --- | --- | --- |
| Recall@5 | 10 обычных | `|R ∩ Top5| / |R|`, среднее |
| MRR@5 | 10 обычных | среднее `1 / rank` первого релевантного документа, 0 если нет в top-5 |
| Accuracy | 10 обычных | доля верных ответов: нет отказа и в ответе есть все `key_facts` (подстрока или совпадение по леммам) |
| Correct Rejection Rate | 5 ловушек | доля корректных отказов: `finish_reason = no_context` или фраза «нет информации» |

Ранжирование для метрик — по документам: документ занимает позицию своего лучшего фрагмента (решение D13). Автопроверка Accuracy строгая и грубая, поэтому текст ответа сохраняется в отчёт для ручной перепроверки.

### Разбор ошибок

Где потеряна информация — по схеме занятия 3 (база → поиск → контекст → ответ):

- **Q08 (указатели), поиск.** D23 на 6-м месте (балл 12.3): определение там дано для «языка С++», а токенизатор отбрасывает однобуквенное «с» из «С++», поэтому слово запроса «Си» не совпадает. На 4-е место вышел D19 (14.9) — те же 4 совпавших слова, но «указатель» встречается чаще (разделы про ссылки и структуры), хотя определения нет.
- **Q09 (рекурсия), поиск.** D22 на 6-м месте (9.4): слайд «Рекурсивные функции» совпадает с запросом только словами «рекурсивный» и «функция», а в D19 есть ещё «рекурсия» и «программирование».
- **Возможные улучшения:** сохранять «С++» и «Си» как один терм, учитывать синонимы обозначений языка; это меняет токенизатор и проверяется следующим прогоном.
- **MRR = 1.0.** Первый документ всегда релевантный: вопросы тематические, и ключевые термины («асимптота», «Хартли», «дополнительный код») редкие, поэтому дают большой IDF. Ограничение: вопросы составлены командой, знающей корпус; к точке 3 нужен отдельный контрольный набор (holdout).
- **Ловушки.** Все 5 отклонены порогом покрытия, но T01 близко к порогу (0.43 при пороге 0.46): слова «экзамен» и «матанализ» в корпусе есть. В режиме `full` второй уровень защиты — инструкция LLM отвечать «В документах нет этой информации».

| coverage | 0.50 | 0.67 | 0.82 | 0.52 | 0.86 | 0.70 | 0.83 | 0.88 | 0.70 | 0.92 |

Порог `0.46` — середина зазора между минимумом обычных (0.50) и максимумом ловушек (0.43). Порог подобран на этих же 15 вопросах, поэтому результат CRR = 1.0 оптимистичен; к точке 3 порог проверяется на holdout.

## Эксперименты

[Прогон 2026-11-19](results/2026-11-19T19-34-53_experiments.md), меняется одна настройка за раз:

| Вариант | Recall@5 | MRR@5 |
| --- | --- | --- |
| База: леммы, стоп-слова, фрагменты 1000, заголовок, k1 = 1.2, b = 0.75 | 0.960 | 1.000 |
| E1: без лемматизации | 0.897 | 1.000 |
| E1: без лемматизации и удаления стоп-слов | 0.888 | 1.000 |
| E1: без удаления стоп-слов | 0.960 | 1.000 |
| E2: фрагменты 500 / 1500 символов | 0.960 / 0.960 | 1.000 |
| E3: без заголовка документа во фрагменте | 0.960 | 1.000 |
| E4: k1 = 2.0; b = 0; b = 1 | 0.960 | 1.000 |

**Вывод.** Лемматизация даёт заметный прирост полноты (+0.063): в русских вопросах и методичках одно понятие встречается в разных формах («указатель / указателя / указатели»). Остальные настройки на 10 вопросах результат не меняют — набор слишком мал, чтобы различить их; выбор оставлен по рекомендациям лекции и проверяется на расширенном наборе к точке 3. Качество ранжирования по метрикам высокое: релевантный документ всегда первый, 96 % релевантных документов в top-5; основные потери — у длинных обзорных документов (D19), которые оттесняют короткие точные фрагменты.
